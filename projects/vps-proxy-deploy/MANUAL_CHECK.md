## 7. NODE04：透明 TUN 与 Docker

只读取证建议：

```bash
ip rule show
ip -4 route show table all
ip -6 rule show
ip -6 route show table all
ip -br link show
systemctl is-active mihomo
```

在当前合法 shell 中，用明确绕过环境代理的请求检查宿主路径：

```bash
curl --noproxy '*' -4 --connect-timeout 8 --max-time 20 \
  --show-error https://api.ip.sb/ip
```

这只能排除 curl 的显式代理环境，**不会排除透明 TUN**。与指定 SOCKS 的请求、路由命中及必要抓包互相印证。保留内部 DNS、公司私网、Docker网桥与现有 `tun0` 的实际路由，不把宽泛的私网 pref100 规则视为普适补丁。

Docker 验收：

1. 定位当前应用容器名及 network mode，不假定旧容器 ID/网关仍有效。
2. 只抽取必要端口、网关和健康状态，不全文输出 `docker inspect .Config.Env`（可能有数据库密码/Token）。
3. 容器 bridge 模式下的 loopback 是容器自身；host 模式另论，不能一概而论。
4. 用已存在的容器内诊断工具发起请求；若需 helper image，先考虑拉取及运行的副作用，不能“没装 curl”就判未走代理。
5. 明确区分：经显式 HTTP 代理出口、容器不设代理的透明 TUN 出口，以及 Sub2API 自身某个账号的实际上游请求。
6. 服务外部可达性必须从另一台机器访问；宿主自己访问自己的 LAN IP 不是充分模拟远端访问。
7. 8080 再次超时，先记录 DNAT、回程到远端源网段的路由、策略规则，再做最小可回滚更改；不先 reset UFW 或重建所有容器。

## 11. 2026-11-17 已知陷阱（动手前先读）

### 11.1 直接写库加客户端 → 永远不会显示流量和在线

现象：客户端能正常连、业务正常，但面板恒为 `0 B` 且「离线」。

原因：x-ui 的流量任务每 10 秒执行一次 `UPDATE client_traffics SET up=up+?, down=down+? WHERE email=?`。只把客户端写进 `inbounds.settings` 的 JSON 而没有同步创建 `client_traffics` 行时，该 `UPDATE` 命中 0 行，**流量被静默丢弃**，`journalctl` 里没有任何报错。面板的「在线」同样依赖流量增量，所以两边一起错。

正确做法：

- 优先在面板里「添加入站客户端」，它会同时建好统计行。
- 若确实要写库，必须补一行（字段名以当前版本为准，先 `.schema client_traffics` 核对）：

```sql
INSERT INTO client_traffics
  (inbound_id, enable, email, up, down, all_time, expiry_time, total, reset, last_online)
VALUES (<入站ID>, 1, '<email>', 0, 0, 0, 0, 0, 0, 0);
```

### 11.2 面板显示 0 B 有三种完全不同的含义，不要混为一谈

| 显示 | 含义 | 怎么区分 |
|---|---|---|
| 0 B + 离线 | 当前确实没有连接 | `ss -tn state established '( sport = :443 )'` 看对端 IP |
| 0 B + 有历史 | 当前计费周期无增量，历史在 `all_time` 字段 | 直接查 `all_time` |
| 0 B + 业务正常 | **缺统计行，流量正在被丢弃** | `xray api statsquery` 有值但库里没有行 |

### 11.3 判断"链路是否真的通"，不要只看面板

```bash
# Xray 内部实时计数（最权威）
/usr/local/x-ui/bin/xray-linux-amd64 api statsquery \
  --server=127.0.0.1:62789 -pattern "user>>>"

# 数据库落盘值
sqlite3 /etc/x-ui/x-ui.db \
  "SELECT email, up, down, all_time FROM client_traffics ORDER BY id;"
```

两者对不上，就是 11.1 那类问题；两者一致且为 0，才是真的没流量。

### 11.4 CDN 备用线路的定位别搞错

Cloudflare 免费 CDN 改的是**源站地址与端口是否暴露**，不改变跨境链路质量。当日实测该线路延迟约 2.6 s、吞吐 350–655 KB/s，明显劣于直连；优选 IP 也没有可测收益。它只能当"主线路全挂"时的兜底，不能当日常主线路，也不要为此付费升级。

### 11.5 备份文件名带前缀便于识别

当日清理前建的备份：`/root/x-ui.db.bak.orphan.*`（清理孤儿行前）、`/root/x-ui.db.bak.clean.*`（正式删除前）。回滚前必须先确认会不会覆盖之后的客户端改动，不要用通配符批量还原。
